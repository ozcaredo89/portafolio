## Problem / goal
Link previews are built by crawlers from Open Graph tags. The first version had a heavy PNG (235 KB, close to WhatsApp's ~300 KB limit), one image for both languages, left-aligned text and no alt text or cache control.

## Scope
- Share card 1200×630 in ES and EN: name, role, pitch, the 8 real project marks and key tech. Centred layout so it survives cropping.
- Exported as JPEG (mozjpeg, 4:4:4) under 200 KB; generated by `npm run og` (Chrome + sharp) from `scripts/og.html`.
- Tags: `og:image` per language with `?v=` cache-buster, `secure_url`, `type`, `alt`, `locale:alternate`, Twitter alt; shorter descriptions.
- `apple-touch-icon.png` (180×180).

## Out of scope
- Profile photo (none provided), analytics, redesign of the site.

- [x] Layout centred; reviewed uncropped and centre-cropped

- [x] `apple-touch-icon.png` present and linked
- [x] Live check with a WhatsApp user agent: tags present, image 200, correct type, size and dimensions
- [x] `npm run lint && npm run typecheck && npm run build` pass; CI green

## Operating notes
- Crawlers cache previews. After changing the cards, bump `OG_VERSION` in `src/layouts/Base.astro`.
- To force a fresh WhatsApp preview of an already-shared URL, share it with a query string (e.g. `?v=2`).
- LinkedIn: refresh with the Post Inspector (linkedin.com/post-inspector). Facebook: Sharing Debugger.
